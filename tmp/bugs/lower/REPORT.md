## Checked and found correct
Integer conversions across all width pairs and edge values (default and -O0, compared with Python). Binary operators on every int type, folded and at run time, including typed-constant folding, shift counts of other types, and comparisons. Mixed-type comparisons are rejected. `==` and `hash` agree for structs with padding, -0.0/0.0, NaN, slices by content, enums with data, tuples, pointers, function values, and Map keys of floats, structs and slices. Struct, array and tuple copies, overlapping self-assignment, Big (SRet) values through calls and returns, tuple-destructuring swaps. Receiver auto-reference (fields, elements, through pointers, Map.ptr, `&` match bindings, globals, temporaries). `defer` order with return, break, continue, labelled loops and `if` values. `match`: tuples of enums, nested Opt, guards, `&` bindings mutating the scrutinee (variables, Vec elements, arrays), pointer patterns, exhaustiveness messages, unreachable arms. Nested and anonymous functions: an outer variable used in body, guard, top pattern, nested block, array literal, defer, method receiver or inner nested function is an error in every case, also in a generic enclosing function. `clone` of Vec (spare capacity of the original untouched), Map (deleted keys), recursive slices, generic structs, enums, arrays, tuples, Opt, string literals. Enum layouts and zero values (Opt is None, first variant). Aggregate constants, `[_]T`, `embed`, function-valued constants, constant assignment and address errors. Overloading and builtin fallback (len, hash, clone). Generic inference errors. Extern functions and variables (types rejected at the C boundary, addresses not allowed in constants, callbacks with qsort). Bounds checks: 46 index and slice forms (Vec len vs capacity, negative indices, a > b, slices of slices, str, arrays in structs and through pointers, constants, `a + n` overflow, u64/u8/i8 indices, compound assignment, swap). Range `for` loops: 600 random type/bound/step cases compared with Python. The copy-write lint was read for false positives and none were found.

## Suspicions not confirmed
- Behaviour not in the reference: `x: u8 = -1` is accepted (255), so a negative decimal literal acts as a bit pattern for unsigned types. Uninstantiated generic functions are not type-checked, which contradicts "all errors, also in functions never called" (the generics section implies it, though). Float to integer conversion out of range is not documented; run time and constants now both give 0x8000000000000000 (u64: 0 beyond 2^64).
- `a: u8 = 1; a == 1.0` reports two errors for one mistake.
