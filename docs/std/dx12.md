# std.dx12

`use std.dx12`. Direct3D 12 and DXGI bindings, generated by `tools/gen_dx12.al` from the
mingw-w64 C headers (`d3d12.h`, `dxgi*.h`, `d3dcommon.h`, `d3d12sdklayers.h`,
`d3dcompiler.h`): 211 enums, 278 structs, 124 COM interfaces with 2667 methods, 133 interface
ids and the exported entry points, plus the few user32 / kernel32 functions a program needs
to open a window.

**Status: runs on Windows** (`alc build --target windows`). `tests/sys/dx12_offscreen.al`
renders with it (device, WARP, D3DCompile, depth buffer, textures, readback) and
`examples/dx12_triangle.al` draws into a window through a swap chain; both were run under Wine
11 on vkd3d (NVIDIA Vulkan driver), on a desktop: see [Wine](#wine) for what that does and does
not prove. `alc check` type-checks a program that uses this module on any system; a build for
Linux stops with

```
error: `CreateEventW` is imported from `kernel32.dll`, a Windows library: build with --target windows ...
```

On Windows every function uses the Win64 calling convention, so AL functions can be passed as
callbacks (`window_proc`). The bindings describe COM methods that return structs the way the
Windows ABI passes them (hidden result pointer after `this`), pass structs of 1, 2, 4 or 8
bytes as integers and larger ones by reference.

The set-up code most programs need (device with WARP fallback, fences, shader compilation with
error text, buffers, readback, a sprite batcher) is in [std.dx12_util](dx12_util.md).

## Mapping rules

| C | AL |
|---|----|
| `UINT`, `DWORD`, enum types, flag types | `u32` (`INT`, `LONG`, `BOOL`, `HRESULT`: `i32`) |
| `UINT64`, `SIZE_T`, `D3D12_GPU_VIRTUAL_ADDRESS` | `u64` |
| `FLOAT` | `f32` |
| `LPCSTR`, `void *` | `*u8`; `LPCWSTR`: `*u16` (see `utf16`) |
| `HANDLE`, `HWND`, `HINSTANCE` | `*u8` |
| enumerators, `#define` constants | typed constants with their C names (`D3D12_RESOURCE_STATE_PRESENT`) |
| `struct` | struct with the same fields and the Windows x64 layout |
| `union` member | a block of words plus one accessor per member returning a typed pointer (`barrier.u_Transition()`) |
| `GUID`, `IID_*` | `struct GUID` and `IID_ID3D12Device := GUID{...}` with the real values |
| interface `ID3D12Device` | `struct ID3D12Device { vt: *ID3D12DeviceVtbl }`; the vtable struct lists the methods in header order as function fields |
| method | a function with the C++ method name whose first parameter is the interface pointer: `device.CreateCommandQueue(&desc, &IID_ID3D12CommandQueue, &queue)` |
| method returning a struct | returns the struct (`heap.GetCPUDescriptorHandleForHeapStart()`); the wrapper passes the hidden result pointer |
| `void **ppv` out-parameter of a method | a pointer to your typed interface variable (`&queue`) |
| exported function | `extern "d3d12.dll" fn D3D12CreateDevice(...) -> i32` and so on |

Method names are shared by many interfaces (`Release`, `GetDesc`, `Map`); overloading on the
interface pointer picks the right one, and inherited methods are generated for every derived
interface, so `swap_chain.Release()` needs no cast. A function named `Map` does not hide the
core `Map[K, V]` type: types and functions are separate namespaces.

## Helpers

| | |
|---|---|
| `SUCCEEDED(hr)` `FAILED(hr)` | |
| `dx_check(hr, what)` | panics with `what` and the HRESULT in hexadecimal on failure |
| `ppv(&iface)` | an interface variable as the `void **` of an exported function: `D3D12CreateDevice(nil, level, &IID_ID3D12Device, ppv(&device))` |
| `com_release(&iface)` | `Release()` if not nil, then sets the variable to nil |
| `utf16(s) -> *u16` | NUL-terminated UTF-16 copy of UTF-8 text (allocates) |

## Samples

`examples/dx12_triangle.al` is a complete windowed program (a spinning triangle with a sprite
overlay; `tests/check/dx12_triangle.al` type-checks it on every test run):

1. The window: `window_open` of [std.window](window.md) (resizable); `win32_hwnd(w)` is the
   HWND for the swap chain, and after each `poll` the loop compares `size(w)` with the back
   buffers (std.window keeps the loop running while the user drags the window's edge).
2. `gpu_open` (std.dx12_util): optional debug layer, `CreateDXGIFactory2`, the first hardware
   adapter from `EnumAdapters1`, else WARP from `EnumWarpAdapter`, `D3D12CreateDevice`, queue, fence.
3. `create_swap_chain`: `CreateSwapChainForHwnd` on the queue (flip-discard, two buffers),
   `QueryInterface` to `IDXGISwapChain3`, `MakeWindowAssociation`, one render-target view per back buffer.
4. `create_pipeline`: HLSL in a raw string compiled with `D3DCompile`, root signature with two
   root constants, input layout, pipeline state, one command allocator per back buffer, the sprite batcher.
5. `render`: waits for the fence value of the back buffer's previous frame (two frames in
   flight), resets its allocator and the list, barriers through the union accessor, clear, root
   constants, draw, sprites, `Present(1, 0)` (vsync; `--no-vsync`: `Present(0, 0)`), signal.
6. `resize`: when the window size changed: wait for the GPU, release the back buffers,
   `ResizeBuffers`, new views. A minimized window (size 0) is not drawn.
7. Device removal: a `Present` (or any call) that fails reports the HRESULT and the removal
   reason (`GetDeviceRemovedReason`) and ends with status 2; `--remove-device N` provokes it
   with `ID3D12Device5::RemoveDevice`.
8. `destroy`: waits for the GPU and releases every object.

`tests/sys/dx12_offscreen.al` renders without a window and checks pixels: a render target
and a depth buffer, two triangles (one behind the cleared depth), sprites from a 2 x 2 atlas,
`CopyTextureRegion` into a readback buffer; once on the first device and once on WARP.

## Wine

Under Wine, Direct3D 12 is vkd3d on Vulkan and DXGI is wined3d. Both tests above ran under Wine
11.21 on an X server (NVIDIA Vulkan driver). What that does not show:

- Without a display (`DISPLAY` unset) no DXGI factory can be made: `CreateDXGIFactory2` and
  `D3D12CreateDevice(nil, ...)` fail with `DXGI_ERROR_UNSUPPORTED` (0x887a0004) because wined3d
  finds no display driver (GL renderer: "Failed to create a window"; Vulkan renderer: "Required
  extension 'VK_KHR_win32_surface' is not available"). `tests/run.sh --target windows`
  therefore reports the offscreen test as SKIP with this message; D3DCompile works headless.
- `EnumWarpAdapter` returns the hardware adapter ("semi-stub"), so WARP itself is untested.
- `ID3D12Device5::RemoveDevice` is a stub: device removal cannot be provoked.
- The flip-model swap effect is ignored (`Ignoring swap effect 0x4`), and there is no debug layer.

## Regenerating and verifying

```
./build/alc run tools/gen_dx12.al               # rewrites std/dx12.al and its test (byte-identical if nothing changed)
./build/alc run tools/gen_dx12.al -- --verify   # also writes tmp/Dx12Bindings/verify.c and has a C compiler check it
```

The generator is an AL program, run from the repository root. It reads the headers from
`/usr/x86_64-w64-mingw32/include` (or `--include DIR`); `--quiet` leaves out the summary.
`std/dx12.al` is embedded in the compiler: rebuild `alc` after regenerating.

`--verify` writes a C file of static assertions (struct sizes, every field offset, the vtable
slot of every method, every constant value) and compiles it against the mingw-w64 headers
(`x86_64-w64-mingw32-gcc -fsyntax-only -w tmp/Dx12Bindings/verify.c`, or clang with
`--target=x86_64-w64-mingw32` if that compiler is not installed; with neither it says so and
ends with status 1). Last run: 278 structs (1066
field offsets), 124 interfaces (2667 vtable slots) and 2993 constants verified. This is a
development-time check of the generator, not part of `alc` or of `verify.sh`.

`tests/std/dx12.al` (also generated) runs on Linux and, with `--target windows`, under Wine:
it compares `sizeof` and field offsets of the AL structs with the values computed from the
headers and makes calls through a COM vtable built in AL.
